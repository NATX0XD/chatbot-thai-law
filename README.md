# ผู้ช่วยจรรยาบรรณวิชาชีพครู (KMUTNB Teacher Ethics Chatbot)

แชตบอตถาม-ตอบเรื่องจรรยาบรรณวิชาชีพทางการศึกษา ตอบจากข้อบังคับคุรุสภาฉบับจริง
และอ้างเลขข้อทุกคำตอบ ต่อกับ LINE ได้ และมีหน้าเว็บไว้ทดสอบก่อนมี LINE channel

ครอบคลุมจรรยาบรรณ 5 ด้านตามข้อบังคับคุรุสภา ว่าด้วยจรรยาบรรณของวิชาชีพ พ.ศ. 2556
คือ ต่อตนเอง ต่อวิชาชีพ ต่อผู้รับบริการ ต่อผู้ร่วมประกอบวิชาชีพ และต่อสังคม

ก่อนหน้านี้ระบบเดียวกันนี้ตอบกฎหมายไทยทั่วไป 733 ฉบับ คลังนั้นยังอยู่ในที่เดิม
และสลับกลับได้ด้วยตัวแปรเดียว — ดู `CORPUS_FILE` ใน `app/config.py`
รายงานการสำรวจ `report/รายงานชุดข้อมูลกฎหมายไทย.md` (106 หน้า) อธิบายคลังชุดนั้น ไม่ใช่ชุดนี้

## โครงสร้างโปรเจกต์

```
thai-law-bot/
├── data/
│   ├── raw/ksp/      PDF คุรุสภา 10 ฉบับ ห้ามแก้ (2.1 MB)
│   ├── ocr/          ผล OCR ของ 4 ฉบับที่ text layer ใช้ไม่ได้ (commit ไว้)
│   ├── eval/         ชุดประเมิน 65 ข้อ เขียนมือ มีเฉลยระดับข้อ
│   ├── processed/    ชุดข้อมูลที่เอาไปใช้จริง ← ผลงานอยู่ตรงนี้
│   └── index/        ดัชนีค้นคืน สร้างใหม่ได้ ลบได้
├── app/              ตัวแชตบอต (retriever, LLM, LINE, API)
├── ingest/           สคริปต์แปลง raw -> processed -> index + ตรวจคุณภาพ
├── docs/             เอกสารทดสอบการใช้งาน 60 เคส + ผลตรวจ
├── report/           รายงาน 106 หน้า (อธิบายคลังกฎหมายทั่วไปชุดก่อน)
├── tests/            342 เทสต์
└── web/              หน้าเว็บทดสอบ
```

รายละเอียดทุก field ของทุกไฟล์อยู่ใน [`data/README.md`](data/README.md)

## ข้อมูลที่ใช้

เอกสารทั้งหมดมาจาก https://www.ksp.or.th/laws/ หมวด "จรรยาบรรณวิชาชีพ" ครบทั้ง 9 ฉบับ
บวกพระราชบัญญัติแม่บทอีก 1 ฉบับ ดึงด้วย `scripts/fetch_ksp.sh` ซึ่งตรึง checksum ไว้ทุกไฟล์

| คีย์ | เอกสาร | ข้อ/มาตรา | อ่านด้วย |
|:---|:---|---:|:---|
| `ksp-2556` | ข้อบังคับคุรุสภา ว่าด้วยจรรยาบรรณของวิชาชีพ พ.ศ. 2556 — **แกนหลัก หมวด 1–5 = ข้อ 7–15** | 15 | text layer |
| `ksp-2550` | ข้อบังคับฯ ว่าด้วยแบบแผนพฤติกรรมตามจรรยาบรรณของวิชาชีพ พ.ศ. 2550 | 24 | PUA map |
| `act-2546` | พระราชบัญญัติสภาครูและบุคลากรทางการศึกษา พ.ศ. 2546 | 90 | legacy map |
| `ksp-2568` | ข้อบังคับฯ ว่าด้วยการพิจารณาการประพฤติผิดจรรยาบรรณฯ พ.ศ. 2568 | 73 | OCR |
| `ksp-2553` | ฉบับ พ.ศ. 2553 — **ถูกยกเลิกโดย 2568** | 61 | PUA map |
| `ksp-2559` | ฉบับที่ 2 พ.ศ. 2559 — **ถูกยกเลิกโดย 2568** | 11 | text layer |
| `ksp-2563` | ฉบับที่ 3 พ.ศ. 2563 — **ถูกยกเลิกโดย 2568** | 8 | OCR |
| `ksp-2549` | ข้อบังคับฯ ว่าด้วยการอุทธรณ์คำวินิจฉัยฯ พ.ศ. 2549 | 28 | PUA map |
| `ksp-2569` | ฉบับที่ 2 พ.ศ. 2569 | 8 | OCR |
| `ksp-ann-appeal` | ประกาศคณะกรรมการคุรุสภา เรื่อง คณะอนุกรรมการอุทธรณ์ฯ | 6 | OCR |

| รายการ | ค่า |
|:---|---:|
| เอกสาร | 10 ฉบับ |
| ข้อและมาตราที่ทำดัชนี | 324 |
| ชิ้นข้อความในดัชนี | 334 |
| ชิ้นที่ติดป้ายจรรยาบรรณ 5 ด้าน | 30 |
| ข้อมูลปรับปรุงถึง | 8 เมษายน พ.ศ. 2569 |

ฉบับที่ถูกยกเลิกยังอยู่ในดัชนี เพราะข้อบังคับฯ 2568 อ้างถึงเรื่องที่เริ่มดำเนินการไว้ตามฉบับเดิม
แต่ถูกลดคะแนนจัดอันดับ และ citation จะมีคำว่า "(ยกเลิกแล้ว)" กำกับเสมอ

**ข้อจำกัดที่ต้องรู้ก่อนใช้** คลังนี้แคบมากโดยตั้งใจ เรื่องที่**ตอบไม่ได้**และอยู่ใกล้ที่สุดคือ

- **วินัยข้าราชการครู** ตาม พ.ร.บ.ระเบียบข้าราชการครูฯ ซึ่งเป็นคนละเรื่องกับจรรยาบรรณ
  มีกระบวนการและบทลงโทษคนละชุด และเป็นทางที่ระบบนี้จะทำให้ครูเข้าใจผิดได้มากที่สุด
- **การขอและต่อใบอนุญาตประกอบวิชาชีพ** เป็นข้อบังคับคุรุสภาเหมือนกัน แต่คนละฉบับ
- **เงินเดือน สัญญาจ้าง ภาษี คดีอาญา คดีแพ่ง** ไม่มีตัวบทในคลังเลย

ทั้งสามกลุ่มนี้ได้ cosine 0.44–0.74 คือ **สูงกว่าเกณฑ์** เพราะทุกคำถามพูดถึงครูและค้นเจอ
ข้อบังคับคุรุสภาจริง เกณฑ์คะแนนจึงกันไม่ได้ ต้องใช้กฎเจาะจงใน `app/coverage.py` แทน

### ทำไมต้องมี guard หลายชั้น

วัดจริงด้วย `ingest/calibrate.py` บนชุดประเมิน 65 ข้อ ได้ผลนี้

| กลุ่มคำถาม | cosine สูงสุด |
|:---|:---|
| ตอบได้ | 0.524 – 0.822 |
| ไม่ใช่คำถามกฎหมาย | 0.318 – 0.397 |
| เป็นคำถามกฎหมายจริง แต่ตัวบทไม่อยู่ในคลัง | 0.438 – 0.742 |

สองกลุ่มแรกแยกกันสะอาดที่ 0.46 แต่กลุ่มที่สาม **ทับกลุ่มแรกทั้งกลุ่ม** และนี่คือกลุ่มที่อันตรายที่สุด
เช่น "ข้าราชการครูทำผิดวินัยร้ายแรงมีโทษอะไร" ได้ cosine 0.742 ค้นไปเจอ พ.ร.บ.สภาครูฯ
ซึ่งเป็นกฎหมายจริงและพูดถึงครูจริง แต่ไม่มีเรื่องวินัยข้าราชการอยู่ในนั้นเลย
ในสายตาของ retriever นี่คือการค้นที่สำเร็จ

คะแนนจึงแยกกรณีนี้ไม่ได้ ทางออกคือกฎเจาะจงใน `app/coverage.py` แบ่งเป็นกฎแข็งกับกฎอ่อน
กฎแข็งทำงานแม้คำถามจะมีคำว่าจรรยาบรรณอยู่ด้วย เพราะวินัยกับจรรยาบรรณใช้ถ้อยคำคล้ายกัน
แต่เป็นคนละเรื่อง ส่วนกฎอ่อนจะหลีกทางให้ เช่น "ผิดจรรยาบรรณแล้วติดคุกไหม" ต้องได้คำตอบ
ไม่ใช่ถูกปฏิเสธเพราะมีคำว่าคุก

**ทำไม guard ชั้นที่ 5 ถึงจำเป็น** ชื่อกฎหมายที่ผิดผู้อ่านเห็นได้เอง แต่ "ตามข้อ 23"
ทั้งที่กฎอยู่ข้อ 13 อ่านเหมือนการอ้างอิงที่ถูกต้องทุกประการ และพาผู้อ่านไปอ่านกฎคนละข้อ
ชั้นนี้ยังจับกรณีเรียกข้อของข้อบังคับว่า "มาตรา" ซึ่งชี้ไปยังสิ่งที่ไม่มีอยู่จริง

**ทำไมต้อง hybrid** คำถามมาสองแบบ ครูที่รู้ศัพท์พิมพ์ "เพิกถอนใบอนุญาต ข้อไหน"
ซึ่ง BM25 จับได้แม่น ส่วนคนทั่วไปพิมพ์ "ครูด่านักเรียนหน้าชั้นผิดไหม" ซึ่ง dense จับได้
บนคลังเล็กขนาดนี้ BM25 มีน้ำหนักมากกว่าเดิมมาก เพราะ "แตกความสามัคคี" ปรากฏในไม่กี่ข้อ
การตรงคำจึงเป็นหลักฐาน ไม่ใช่ความบังเอิญเหมือนตอนที่คลังมี 29,485 ชิ้น

**ทำไมไม่ใช้ vector database** 334 เวกเตอร์ × 1024 มิติ แบบ float16 = 0.7 MB
โหลดเข้าหน่วยความจำแล้วคูณเมทริกซ์ครั้งเดียวก็ค้นเสร็จในหลักไมโครวินาที

## ติดตั้ง

ต้องมี Python 3.11 ขึ้นไป (torch ≥ 2.6 ไม่รองรับ 3.9)

```bash
cd thai-law-bot
python3.11 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env          # แล้วใส่คีย์
```

### สร้างดัชนี

```bash
./scripts/fetch_ksp.sh                       # ดึง PDF 10 ฉบับ (2.1 MB) ตรวจ checksum
.venv/bin/python -m ingest.extract_ksp       # raw/ksp -> processed/corpus_ksp.jsonl
.venv/bin/python -m ingest.audit_ksp         # ตรวจความสมบูรณ์ 6 ด่าน ต้องผ่านครบ
.venv/bin/python -m ingest.build_index       # processed -> index (~15 วินาที)
```

ขั้นที่สองต้องอ่าน PDF สี่ฉบับด้วย OCR ของ macOS (Vision framework) ผลถูก cache ไว้ใน
`data/ocr/` และ commit ลง repo แล้ว เครื่องที่ไม่ใช่ macOS จึงสร้างดัชนีได้โดยไม่ต้องมี Vision
ลบไฟล์ใน `data/ocr/` ถ้าต้องการให้อ่านใหม่

`ingest.audit_ksp` ไม่ใช่เทสต์ซ้ำ เทสต์ตรวจว่า parser ทำงานถูก ส่วนตัวนี้ตรวจว่า
**ข้อมูลออกมาครบ** ซึ่งเทสต์ตรวจไม่ได้ เพราะไม่มีเทสต์ไหนรู้ว่าเอกสารมีกี่ข้อ
รายงานผลอยู่ที่ `data/processed/corpus_ksp_audit.md`

กลับไปใช้คลังกฎหมายทั่วไปชุดเดิมได้ด้วย

```bash
CORPUS_FILE=corpus.jsonl .venv/bin/python -m ingest.build_index
```

แต่เกณฑ์คะแนนและกฎใน `app/coverage.py` ถูกจูนมาเพื่อคลังจรรยาบรรณ ทั้งสองอย่างเป็นของคู่กัน

### รัน

```bash
.venv/bin/uvicorn app.main:app --reload --port 8000
```

เปิด http://localhost:8000 เพื่อทดสอบผ่านหน้าเว็บ

## ต่อกับ LINE

ยังไม่ต้องมี channel ก็รันได้ ระบบจะปิดเฉพาะส่วน `/webhook` ไว้ เมื่อพร้อมแล้วทำตามนี้

1. สร้าง Provider และ **Messaging API channel** ที่ https://developers.line.biz/console/
2. คัดลอกค่าลง `.env`
   - `LINE_CHANNEL_SECRET` — แท็บ *Basic settings*
   - `LINE_CHANNEL_ACCESS_TOKEN` — แท็บ *Messaging API* กด issue แบบ long-lived
3. เปิดพอร์ตออกอินเทอร์เน็ต ตอนพัฒนาใช้ `ngrok http 8000` หรือ `cloudflared tunnel --url http://localhost:8000`
4. ในแท็บ *Messaging API* ตั้ง **Webhook URL** เป็น `https://<โดเมนของคุณ>/webhook` แล้วกด Verify
5. เปิด *Use webhook* และ **ปิด** *Auto-reply messages* กับ *Greeting messages*
   ไม่งั้น LINE จะตอบข้อความอัตโนมัติทับคำตอบของบอต

### ข้อจำกัดเรื่องเวลาที่ต้องรู้

LINE คาดหวังให้ webhook ตอบ 200 ภายในไม่กี่วินาที และ reply token หมดอายุราว 30 วินาที
แต่ RAG + Typhoon ใช้เวลานานกว่านั้นได้ โค้ดจึงตอบ 200 ทันทีแล้วประมวลผลใน background task
ถ้า reply token หมดอายุก่อนจะสลับไปใช้ push API ให้เอง

## API

| เส้นทาง | ใช้ทำอะไร |
|:---|:---|
| `GET /` | หน้าเว็บทดสอบ |
| `GET /health` | สถานะดัชนีและคีย์ที่ตั้งค่าไว้ |
| `POST /chat` | `{"question": "..."}` -> คำตอบ + มาตราที่ใช้ตอบ |
| `GET /search?q=...` | ค้นอย่างเดียว ไม่เรียก LLM — ใช้จูน `MIN_DENSE_SIM` โดยไม่เปลืองโควตา |
| `GET /stats` | ขนาดคลังและค่าพารามิเตอร์ที่ใช้อยู่ |
| `GET /recent?token=...` | ใครถามอะไร บอทตอบอะไร ปิดอยู่ถ้าไม่ตั้ง `MONITOR_TOKEN` |
| `POST /webhook` | LINE (ตรวจลายเซ็นก่อนเสมอ) |

ยิงจาก Postman ได้ด้วยไฟล์ `postman/thai-law-bot.postman_collection.json` — Import เข้า Postman
แล้วตั้งตัวแปร `baseUrl` กับ `monitorToken` วิธีใช้อยู่ใน `CLAUDE.md` หัวข้อ 5

| `test_line_bot.py` | ตรวจลายเซ็น LINE รับของจริง ปฏิเสธของปลอม/ของที่ถูกแก้ |

### วัดการค้นคืน

ชุดประเมิน `data/eval/ksp_questions.jsonl` เขียนมือ 65 ข้อ — ตอบได้ 50 ข้อพร้อมเฉลยระดับข้อ
ปฏิเสธ 15 ข้อ วัดด้วย `python -m ingest.tune_fusion`

| วิธีค้น | doc@1 | doc@3 | rule@1 | rule@6 |
|:---|---:|---:|---:|---:|
| hybrid 1.0:1.0 (ที่ใช้จริง) | 78% | 94% | 68% | **96%** |
| 3.0:0.25 (ค่าของคลังเดิม) | 82% | 88% | 66% | 92% |
| dense อย่างเดียว | 82% | 90% | 58% | 92% |

`rule@6` คือข้อที่ตอบคำถามได้โผล่อยู่ในหกชิ้นที่ส่งให้โมเดลไหม เป็นตัวชี้ว่าคำตอบที่ถูก
"เอื้อมถึงได้หรือไม่" ส่วน `doc@1` บอกแค่ว่าโมเดลต้องอ่านมากแค่ไหนกว่าจะเจอ

ปรับ threshold ด้วย `python -m ingest.calibrate` ซึ่งพิมพ์การกระจายคะแนนของทั้งสามกลุ่ม
พร้อมบอกว่าค่าปัจจุบันปล่อยคำถามนอกขอบเขตรั่วกี่ข้อ ถ้าเปลี่ยนโมเดล embedding ต้องรันใหม่เสมอ

**ข้อจำกัดของตัวเลขชุดนี้** ชุดประเมิน 65 ข้อเขียนโดยผู้สร้างระบบเอง เล็กเกินกว่าจะอ้างเป็น
ผลวัดเชิงสถิติ และมีอคติของผู้เขียนแน่นอน ใช้ตั้งเกณฑ์และจับการถดถอยได้ แต่อ้างความแม่นยำไม่ได้

### วัดคุณภาพคำตอบ

`docs/ksp-acceptance-tests.md` มี 60 เคส เขียนจากตัวบท PDF **ก่อน** แก้โค้ดของแอป
แต่ละเคสระบุว่าต้องอ้างข้อไหน คำตอบต้องมีอะไร และต้องไม่มีอะไร

ผู้ตรวจเป็น agent คนละตัวกับผู้เขียนโค้ด ได้รับแค่เอกสารทดสอบ ไฟล์ PDF ต้นฉบับ และวิธียิง API
ไม่ได้รับซอร์สของแอปและไม่มีสิทธิ์แก้ไฟล์ ผลอยู่ที่ `docs/ksp-acceptance-results.md`

## สิ่งที่ยังไม่ได้ทำ

- **ชุดประเมินเล็กเกินไป** 65 ข้อเขียนเอง ใช้ตั้งเกณฑ์ได้ แต่อ้างความแม่นยำไม่ได้
  ขั้นต่อไปคือให้ครูจริงเขียนคำถามมาโดยไม่เห็นตัวบท
- **OCR ยังมี typo ระดับตัวอักษร** เอกสารสี่ฉบับที่ผ่าน Vision มีคำเพี้ยนราว 0.8% ของคำหลัก
  (เช่น "กล่าวไทษ" แทน "กล่าวโทษ" 2 จุดจาก 263) เลขข้อและเลขมาตราถูกต้องทั้งหมด
  ซึ่งเป็นส่วนที่กระทบการอ้างอิง แต่คำที่เพี้ยนทำให้ BM25 พลาดคำนั้นได้
- **ข้อบังคับคุรุสภาฉบับอื่นยังไม่ได้ดึง** ใบอนุญาตประกอบวิชาชีพ มาตรฐานวิชาชีพ ค่าธรรมเนียม
  ตอนนี้ปฏิเสธพร้อมชี้ทาง การเพิ่มเข้ามาคืองานที่คุ้มที่สุดถ้าจะขยายต่อ
- **Reranker** ตอนนี้ใช้ RRF ล้วน การเพิ่ม cross-encoder จะแม่นขึ้นแต่ช้าลง
- **จำบทสนทนา** ตอบทีละคำถาม ไม่จำบริบทก่อนหน้า
- **ยังไม่ได้วัดเวลาตอบใต้โหลดจริง** ทดสอบเดี่ยวได้ 5–25 วินาที ขึ้นกับความยาวคำตอบ
- **coverage rule ยังเป็น keyword** `app/coverage.py` ใช้การจับคำ ซึ่งพลาดได้ทั้งสองทาง
  บนคลังแคบขนาดนี้ต้นทุนของการพลาดสูงกว่าเดิม เพราะสิ่งที่อยู่นอกขอบเขตมีมากกว่าสิ่งที่อยู่ใน
- **`report/` อธิบายคลังชุดก่อน** รายงาน 106 หน้าเป็นของคลังกฎหมายทั่วไป ยังไม่ได้เขียนใหม่

## บันทึกปัญหาที่เจอระหว่างสร้าง

เก็บไว้เพราะทั้งสามข้อไม่มีอาการฟ้อง ระบบทำงานได้ปกติแต่ให้ผลผิด

**1. BGE-M3 บน MPS ให้เวกเตอร์ผิดเมื่อ encode ทีละข้อความ**
cosine เทียบกับผลบน CPU เหลือ 0.30 ในบางคำถาม แต่ถ้า encode เป็น batch ได้ 1.0000 พอดี
ดัชนีจึงไม่เสีย (สร้างด้วย batch 16) แต่ตอน query พังเงียบ ๆ ทำให้ "นายจ้างหักเงินเดือนได้ไหม"
ได้ cosine 0.2530 และค้นไปเจอ พ.ร.บ.การรับขนคนโดยสาร แก้โดยบังคับ encode query บน CPU
ตรวจซ้ำด้วยการสุ่ม 300 chunk มาเทียบกับ CPU แล้วได้ cosine 1.0000 ทุกตัว

**2. RRF ฝัง "คำตอบที่ถูกที่สุด" ไว้ท้ายแถว**
"ถูกเลิกจ้างกะทันหัน ได้ค่าชดเชยเท่าไหร่" มี ม.118 เป็นอันดับ 1 ฝั่ง dense (0.667) แต่ BM25
ไม่ติด top-30 จึงได้แต้ม 1/61 ส่วน ม.119-122 ที่กลาง ๆ ทั้งสองฝั่งได้ราว 1/31+1/31 แล้วแซงขึ้นไป
ผลคือมาตราที่ระบุอัตราค่าชดเชยจริงหลุด top-10 แก้โดยสำรองที่นั่งให้ผลอันดับต้นของแต่ละฝั่ง

**3. คะแนน RRF ใช้เป็น guardrail ไม่ได้เลย**
RRF คิดจากอันดับล้วน "สูตรทำต้มยำกุ้ง" จึงได้คะแนนสูงสุด 0.0164 เท่ากับคำถามแรงงานที่ตรงเป๊ะ
guard เดิมที่ตั้งบน RRF จึงไม่มีผลใด ๆ ย้ายไปวัดที่ cosine ดิบแทน และตัด BM25 ออกจาก guard
เพราะวัดแล้วพบว่าคำถามนอกเรื่องได้ BM25 สูงถึง 15.1 ขณะที่คำถามที่ตอบได้ต่ำสุดอยู่ที่ 12.6

**4. text layer ที่วรรณยุกต์หายทั้งฉบับ ไม่มีอาการฟ้องอะไรเลย**
PDF ห้าฉบับผลักวรรณยุกต์ไปไว้ใน Private Use Area และอีกฉบับเข้ารหัสไทยไว้หลัง cmap
แบบ Mac Roman อ่านออกมาได้ข้อความที่ดู "เป็นไทย" ครบถ้วนแต่ไม่มีวรรณยุกต์เลย
`ตอง` กับ `ต้อง` tokenise ไม่เหมือนกัน BM25 จึงเลิกแมตช์เงียบ ๆ
แก้ด้วยตารางที่อ่านจากตัวเอกสารเองทีละคำ และด่านตรวจสัดส่วนวรรณยุกต์ต่อพยัญชนะ

**5. ข้อบังคับฯ 2563 วางกลิฟความกว้างศูนย์ผิดตำแหน่ง**
`ทำรายงาน` ออกมาเป็น `ท ารายงาน` 43 จุด ขณะที่ทุกอัตราส่วนยังดูปกติดี
พยัญชนะตามด้วยช่องว่างแล้วสระอาไม่มีในภาษาไทยจริง จึงใช้เป็นลายนิ้วมือได้
เอกสารฉบับนี้ตกไปใช้ OCR แทน

**6. ทุกฉบับเขียน `ำ` เป็นสองกลิฟ รวม 648 จุด**
Unicode NFC ไม่รวม `ํ` + `า` ให้ pythainlp จึงตัด `ดำเนิน` เป็น `ดํา` + `เนิน`
และ BM25 ไม่เจอคำที่คนพิมพ์จริง

**7. tesseract อ่านเลขไทยผิดเป็นระบบ**
บนข้อบังคับฯ 2568 มันอ่านลำดับ ข้อ ๑..๙ เป็น 1 2 3 5 5 2 3 5 5 และ พ.ศ. ๒๕๖๘ เป็น ๒๕๒๐๕
ทุกการอ้างอิงของบอทนี้คือตัวเลข เครื่องมือที่อ่านตัวเลขไม่ได้จึงใช้ไม่ได้
เปลี่ยนไปใช้ Vision ของ macOS ซึ่งอ่านหน้าเดียวกันได้เลขถูกหมด

**8. โมเดลย่อชื่อข้อบังคับเอง แล้วไปตรงกับฉบับอื่น**
ข้อบังคับฯ แบบแผนพฤติกรรม 2550 ถูกย่อเป็น "ข้อบังคับฯ จรรยาบรรณ 2550" ซึ่งเป็นชื่อของ
คนละฉบับ guard ตรวจ citation จึงทิ้งคำตอบที่ถูกต้องทั้งหมด แก้โดยใส่ชื่อย่อทางการ
ลงใน corpus แล้วให้โมเดลคัดลอกไปใช้
