# เปลี่ยน dataset เป็นจรรยาบรรณวิชาชีพครู (ข้อบังคับคุรุสภา)

วันที่ 23 กันยายน 2569

## เป้าหมาย

เปลี่ยนคลังที่บอทค้น จาก **กฎหมายไทยทั่วไป 733 ฉบับ / 29,485 ชิ้น** เป็น
**จรรยาบรรณวิชาชีพครูตามข้อบังคับคุรุสภา** โดยครอบคลุมองค์ประกอบ 5 ด้าน

| ด้าน | สาระ |
|:---|:---|
| จรรยาบรรณต่อตนเอง | มีวินัยในตนเอง พัฒนาตนเองด้านวิชาชีพ บุคลิกภาพ วิสัยทัศน์ ให้ทันต่อการเปลี่ยนแปลงของสังคมและเทคโนโลยี |
| จรรยาบรรณต่อวิชาชีพ | รักและศรัทธาในวิชาชีพ รับผิดชอบ รักษาชื่อเสียงและมาตรฐานของวิชาชีพครู |
| จรรยาบรรณต่อผู้รับบริการ | ให้ความสำคัญต่อผู้เรียน บริการด้วยความจริงใจ เสมอภาค ไม่เลือกปฏิบัติ ส่งเสริมให้ผู้เรียนพัฒนาเต็มศักยภาพ |
| จรรยาบรรณต่อผู้ร่วมประกอบวิชาชีพ | ร่วมมือ ช่วยเหลือ สนับสนุน ด้วยความเคารพและความสามัคคี |
| จรรยาบรรณต่อสังคม | ประพฤติตนเป็นแบบอย่างที่ดี รับผิดชอบต่อสังคม มีส่วนร่วมพัฒนาชุมชนและสังคม |

ทั้งห้าด้านตรงกับ **หมวด 1–5 ของข้อบังคับคุรุสภา ว่าด้วยจรรยาบรรณของวิชาชีพ พ.ศ. 2556**
(ข้อ 7 ถึง ข้อ 11) แบบหนึ่งต่อหนึ่ง จึงใช้ตัวบทเป็นแกนได้โดยตรง

## ขอบเขต

**ในขอบเขต** ดึงเอกสารคุรุสภา 10 ฉบับ แปลงเป็น corpus สคีมาเดียวกับของเดิม
สร้างดัชนีใหม่ ปรับ guard/citation/query expansion ให้เข้ากับโดเมนครู
คาลิเบรตเกณฑ์ใหม่ และเขียนชุดเทสต์ใหม่

**นอกขอบเขต** ไม่แก้ `report/` (รายงาน 106 หน้า) ไม่แตะ `data/raw/*.parquet`
และ `data/processed/corpus.jsonl` ของเดิม ไม่เปลี่ยนสถาปัตยกรรม retrieval
(ยังเป็น BM25 + dense + RRF เหมือนเดิม)

## 2. การสกัดข้อความ

ตรวจแล้วว่า PDF ทั้งสิบแบ่งเป็นสี่ชั้นคุณภาพ ต่างกันที่วิธีเข้ารหัสฟอนต์
ท่อสกัดจึงต้องเป็นขั้นบันได ไม่ใช่ทางเดียว

### ชั้นที่ 1 — text layer สะอาด

`ksp-2556` อ่านด้วย PyMuPDF ได้ข้อความถูกต้องทันที ตรวจแล้วมีทั้งสระและวรรณยุกต์ครบ

### ชั้นที่ 2 — text layer ที่วรรณยุกต์อยู่ในช่วง PUA

`ksp-2550` `ksp-2549` `ksp-2553` `ksp-2559` `ksp-2563` ใช้ฟอนต์ AngsanaUPC
ที่ผลักวรรณยุกต์และสระบนไปไว้ใน Private Use Area แก้ด้วยตารางแทนที่คงที่
ยืนยันทุกตัวจากบริบทจริงในเอกสารแล้ว

| PUA | อักขระจริง | หลักฐาน |
|:---|:---|:---|
| `U+F701` | `ิ` | `ปกปด` → ปกปิด |
| `U+F706` | `้` | `ปกปอง` → ปกป้อง, `เปาหมาย` → เป้าหมาย |
| `U+F70A` | `่` | `ผู้รวม` → ผู้ร่วม, `ตัวอยาง` → ตัวอย่าง |
| `U+F70B` | `้` | `หนา` → หน้า, `ขอ` → ข้อ |
| `U+F70E` | `์` | `ประสงค` → ประสงค์, `ศิษย` → ศิษย์ |
| `U+F710` | `ั` | `ปญญา` → ปัญญา, `ฟง` → ฟัง |
| `U+F712` | `็` | `เปน` → เป็น |

ตารางเขียนให้ครอบช่วง `U+F700`–`U+F71A` ทั้งช่วง ตัวที่ยังไม่เจอในเอกสารชุดนี้
ให้ map ตามมาตรฐานฟอนต์ไทยของ Microsoft และมีเทสต์คุมทีละตัว

### ชั้นที่ 3 — legacy encoding

`act-2546` สกัดออกมาเป็นอักษรละตินมีเครื่องหมาย เช่น `Àπâ“` ซึ่งคือ `หน้า`
เกิดจากฟอนต์ใช้การเข้ารหัสไทยแบบเก่าที่ไม่ประกาศ ToUnicode
แก้ด้วยตารางแปลงไบต์ต่อไบต์ สร้างตารางจากการเทียบข้อความช่วงที่รู้คำตอบแน่นอน
(ชื่อพระราชบัญญัติ หัวกระดาษราชกิจจานุเบกษา เลขไทย) แล้วตรวจด้วยเกณฑ์ในหัวข้อถัดไป

### ชั้นที่ 4 — ต้อง OCR

`ksp-2568` `ksp-2569` `ksp-ann-appeal` ใช้ฟอนต์ subset ที่ cmap เป็นเลขดัชนี glyph ล้วน
กู้ด้วยตารางไม่ได้ ต้องเรนเดอร์เป็นภาพแล้ว OCR

ใช้ `tesseract` ภาษา `tha` เรนเดอร์ที่ 300 dpi ต้องติดตั้งเพิ่ม

```bash
brew install tesseract tesseract-lang
```

ถ้าไม่มี `tesseract` ในเครื่อง ให้ `extract_ksp.py` **ล้มทันทีพร้อมบอกคำสั่งติดตั้ง**
ไม่ใช่ข้ามเอกสารเงียบ ๆ เพราะเอกสารสามฉบับนี้รวมถึงฉบับปัจจุบันปี 2568

### เกณฑ์ตรวจคุณภาพ

ทุกเอกสารต้องผ่านด่านเดียวกันก่อนเขียนลง corpus ไม่ว่ามาจากชั้นไหน

1. สัดส่วนอักขระไทยต่ออักขระทั้งหมด ≥ 0.80
2. ไม่เหลืออักขระในช่วง PUA (`U+E000`–`U+F8FF`) แม้แต่ตัวเดียว
3. ไม่เหลืออักขระควบคุม (`U+0000`–`U+001F` ยกเว้นขึ้นบรรทัดใหม่)
4. สัดส่วนวรรณยุกต์ต่อพยัญชนะอยู่ในช่วง 0.08–0.35 ซึ่งเป็นช่วงปกติของร้อยแก้วไทย
   ด่านนี้จับกรณีที่วรรณยุกต์หายทั้งฉบับ ซึ่งด่านที่ 1 กับ 2 มองไม่เห็น
5. พบคำหลักที่ต้องมีแน่ ๆ อย่างน้อยหนึ่งคำ (`จรรยาบรรณ` `วิชาชีพ` `คุรุสภา`)

เอกสารที่ไม่ผ่าน ให้เลื่อนไปชั้นถัดไป ถ้าตกตั้งแต่ชั้น OCR ให้ล้มทั้ง pipeline
พร้อมรายงานว่าฉบับใดตกด่านใด ไม่ข้าม

## 3. สคีมา corpus

`data/processed/corpus_ksp.jsonl` หนึ่งบรรทัดต่อหนึ่งข้อหรือหนึ่งมาตรา
ใช้ field เดิมทุกตัวเพื่อให้ `retriever.py` `corpus_store.py` `build_index.py` ไม่ต้องแก้
แล้วเติมของใหม่สี่ตัว

| field | ชนิด | ความหมาย | ตัวอย่าง |
|:---|:---|:---|:---|
| `id` | string | `sysid-หมายเลข[-ท่อน]` | `ksp-2556-7` |
| `act` | string | ชื่อเอกสาร | `ข้อบังคับคุรุสภา ว่าด้วยจรรยาบรรณของวิชาชีพ พ.ศ. 2556` |
| `act_full` | string | ชื่อเต็มตามต้นฉบับ | เหมือน `act` |
| `sysid` | string | คีย์เอกสาร | `ksp-2556` |
| `section` | string | เลขข้อหรือเลขมาตรา เลขอารบิก | `7` |
| `part` | int | ท่อนที่ กรณียาวเกิน 1,800 ตัวอักษร | `0` |
| `text` | string | เนื้อความ normalize แล้ว | `ผู้ประกอบวิชาชีพทางการศึกษา ต้องมีวินัยในตนเอง...` |
| `chapters` | list[string] | หมวดและส่วนที่ข้อนี้สังกัด | `["หมวด 1 จรรยาบรรณต่อตนเอง"]` |
| `n_chars` | int | ความยาว `text` | `142` |
| `unit` | string | `"ข้อ"` หรือ `"มาตรา"` | `ข้อ` |
| `ethics_category` | string หรือ null | หนึ่งใน 5 ด้าน หรือ null ถ้าไม่สังกัดด้านใด | `ต่อตนเอง` |
| `source_url` | string | ลิงก์ PDF ต้นทาง | `https://ratchakitcha.soc.go.th/documents/1986083.pdf` |
| `published` | string | วันประกาศราชกิจจานุเบกษา `YYYY-MM-DD` พ.ศ. | `2556-10-04` |

`unit` จำเป็นเพราะข้อบังคับคุรุสภานับเป็น "ข้อ" ส่วนพระราชบัญญัตินับเป็น "มาตรา"
การอ้างอิงในคำตอบต้องใช้คำให้ตรงชนิด มิฉะนั้นจะเขียนว่า "มาตรา 7 ของข้อบังคับ" ซึ่งผิด

`ethics_category` ใช้ค่าคงที่ห้าค่า `ต่อตนเอง` `ต่อวิชาชีพ` `ต่อผู้รับบริการ`
`ต่อผู้ร่วมประกอบวิชาชีพ` `ต่อสังคม` เติมจากหัวหมวดของเอกสาร ไม่ใช่เดาจากเนื้อความ
เอกสารที่ไม่มีโครงหมวดแบบนี้ (ขั้นตอนสอบสวน อุทธรณ์ พระราชบัญญัติ) ให้เป็น `null`

### การตัดท่อน

ใช้เกณฑ์เดิม 1,800 ตัวอักษร ตัดที่ขอบเขตอนุมาตรา `(๑)` `(ก)` ก่อน ถ้ายังยาวจึงตัดที่ประโยค
`ksp-2550` เป็นฉบับเดียวที่จะโดนตัดบ่อย เพราะหนึ่งข้อบรรจุรายการพฤติกรรมยาว

## 4. โครงไฟล์

### ไฟล์ใหม่

```
scripts/fetch_ksp.sh              ดึง PDF 10 ฉบับลง data/raw/ksp/ ตรวจ checksum
ingest/extract_ksp.py             raw/ksp/*.pdf -> processed/corpus_ksp.jsonl
ingest/thai_pdf_text.py           ชั้นสกัด+normalize: PUA, legacy, OCR, เกณฑ์ตรวจ
ingest/audit_ksp.py               ตรวจความสมบูรณ์ของ corpus -> รายงาน (หัวข้อ 7.1)
data/eval/ksp_questions.jsonl     ชุดประเมินเขียนมือ 60 ข้อ ใช้ปรับเกณฑ์ตัวเลข
docs/ksp-acceptance-tests.md      เอกสารทดสอบการใช้งาน 60 เคส (หัวข้อ 7.2)
docs/ksp-acceptance-results.md    ผลตรวจจาก agent อิสระ รายเคส
```

แยก `thai_pdf_text.py` ออกจาก `extract_ksp.py` เพราะสองงานนี้เปลี่ยนด้วยเหตุคนละอย่าง
ตัวแรกรับผิดชอบ "ทำให้ PDF ออกมาเป็นข้อความไทยที่ถูกต้อง" ตัวหลังรับผิดชอบ
"แบ่งข้อความเป็นข้อและติดป้ายหมวด" ทดสอบแยกกันได้ ตัวแรกทดสอบด้วยสตริงล้วนไม่ต้องมี PDF

### ไฟล์ที่แก้

| ไฟล์ | แก้อะไร |
|:---|:---|
| `app/config.py` | เพิ่ม `CORPUS_PATH` ค่าเริ่มต้น `data/processed/corpus_ksp.jsonl` |
| `app/coverage.py` | กลับตรรกะ จากเดิมระบุหมวดที่ขาด เป็นระบุโดเมนที่รับ |
| `app/numbers.py` | รู้จัก `ข้อ ๗` และ `ข้อ 7` เทียบเท่า `มาตรา` |
| `app/verify.py` | citation guard ตรวจว่าคำนำหน้าตรงกับ `unit` ของชิ้นที่อ้าง |
| `app/query_expand.py` | คำพ้องสายครู |
| `app/answer.py` | prompt และ disclaimer พูดถึงจรรยาบรรณวิชาชีพ ไม่ใช่กฎหมายทั่วไป |
| `README.md` `data/README.md` | ตัวเลขและขอบเขตชุดใหม่ |

`retriever.py` `build_index.py` `build_bm25_compact.py` `embed.py` `corpus_store.py`
`bm25_lite.py` ไม่ต้องแก้ เพราะสคีมาเข้ากันได้

## 5. ชั้นปฏิเสธ

เดิมบอทตอบกฎหมายทั่วไปแล้วปฏิเสธเฉพาะหมวดที่คลังขาด ใหม่กลับด้าน
คลังแคบมาก จึงต้องปฏิเสธทุกอย่างที่อยู่นอกจรรยาบรรณวิชาชีพทางการศึกษา

`app/coverage.py` เขียนใหม่เป็นกฎสองชุด

**ชุดรับ** คำถามที่แตะจรรยาบรรณ วินัย โทษทางจรรยาบรรณ ใบอนุญาตประกอบวิชาชีพ
การสอบสวน การอุทธรณ์ หรือพฤติกรรมของครูต่อศิษย์ เพื่อนร่วมงาน และสังคม

**ชุดปฏิเสธพร้อมเหตุผล** คำถามกฎหมายทั่วไปที่คลังใหม่ไม่มีแล้ว เช่น แรงงาน อาญา แพ่ง
ภาษี ครอบครัว ให้ตอบว่าระบบนี้ครอบคลุมเฉพาะจรรยาบรรณวิชาชีพทางการศึกษา
ไม่เดาและไม่เรียก LLM

คงหลักเดิมไว้ คือกฎเจาะจงมาก่อนคะแนน cosine เพราะคะแนนแยกกรณี
"เป็นคำถามกฎหมายจริงแต่ไม่อยู่ในคลัง" ไม่ได้ และกรณีนั้นอันตรายที่สุด
ยิ่งคลังแคบลง 80 เท่า กรณีนี้ยิ่งเจอบ่อยขึ้น

## 7.1 ตรวจความสมบูรณ์ของ dataset

เทสต์ในหัวข้อ 7 ตรวจว่าโค้ดทำงานถูก ไม่ได้ตรวจว่า **ข้อมูลครบและตรงต้นฉบับ**
สองเรื่องนี้พังคนละแบบ จึงต้องมีด่านแยก

`ingest/audit_ksp.py` รันหลังสร้าง corpus พิมพ์รายงานออกหน้าจอและเขียนลง
`data/processed/corpus_ksp_audit.md` ตรวจหกเรื่อง

1. **เลขข้อครบ** แต่ละฉบับเลขข้อต้องเรียง 1..N ไม่ข้าม ไม่ซ้ำ ข้อที่ขาดให้ระบุเลขออกมา
2. **นับได้ตามต้นฉบับ** จำนวนข้อของแต่ละฉบับเทียบกับตัวเลขที่นับจาก PDF ด้วยมือ
   เก็บค่าที่คาดไว้เป็นตารางคงที่ในไฟล์ ต่างเมื่อไรให้ฟ้อง
3. **ห้าด้านครบ** `ethics_category` ต้องมีครบทั้งห้าค่า และ `ksp-2556` ต้องมีข้อ 7–11
   ติดป้ายครบทั้งห้าด้าน ด้านละอย่างน้อยหนึ่งข้อ
4. **ข้อความไม่ถูกตัดหาย** ทุกชิ้นต้องจบด้วยอักขระที่สมเหตุสมผล ไม่ใช่กลางคำ
   ผลรวม `n_chars` ของแต่ละฉบับต้องไม่ต่ำกว่า 85% ของจำนวนอักขระไทยใน PDF ต้นฉบับ
5. **ไม่มีขยะตกค้าง** หัวกระดาษราชกิจจานุเบกษา เลขหน้า และท้ายกระดาษ
   ต้องไม่ปนอยู่ใน `text` ตรวจด้วยการค้นคำ `ราชกิจจานุเบกษา` และ `เล่ม ... ตอน`
6. **เทียบตัวบทกับองค์ประกอบห้าด้าน** ข้อความของข้อ 7–11 ต้องมีคำหลักของด้านนั้นจริง
   เช่น ข้อ 7 ต้องมี `วินัยในตนเอง` ข้อ 9 ต้องมี `ผู้รับบริการ` หรือ `ศิษย์`
   ด่านนี้จับกรณีที่ parse ถูกแต่จับคู่หมวดสลับกัน

รายงานต้องแสดงทุกฉบับพร้อมสถานะ ผ่านหรือไม่ผ่านทีละข้อ ไม่ใช่สรุปรวมว่า OK
ฉบับใดไม่ผ่าน ให้ขึ้นหัวข้อแยกพร้อมตัวอย่างข้อความที่มีปัญหา

## 7.2 เอกสารทดสอบการใช้งาน และการตรวจโดย agent อิสระ

เทสต์ที่คนเขียนโค้ดเขียนเอง มีแรงจูงใจให้เขียนให้ผ่าน จึงแยกงานสองอย่างนี้ออกจากกัน
คนเขียนโค้ดไม่ได้เป็นคนตัดสินว่าคำตอบดีพอ

### เอกสารทดสอบ

`docs/ksp-acceptance-tests.md` เขียน **ก่อน** เริ่มแก้แอป เขียนจากตัวบท PDF อย่างเดียว
ไม่เปิดโค้ดบอท แต่ละเคสมีหกช่อง

| ช่อง | ความหมาย |
|:---|:---|
| รหัส | `KSP-001` |
| คำถาม | คำถามอย่างที่ผู้ใช้จริงพิมพ์ |
| ด้าน | หนึ่งในห้าด้าน หรือ `กระบวนการ` หรือ `นอกโดเมน` |
| ตัวบทที่ต้องอ้าง | เลขข้อหรือมาตราและฉบับ เช่น `ข้อ 9 ของข้อบังคับฯ 2556` |
| สิ่งที่คำตอบต้องมี | สาระที่ขาดไม่ได้ เขียนเป็นข้อ ๆ |
| สิ่งที่คำตอบต้องไม่มี | เช่น อ้างฉบับที่ถูกยกเลิก เดาเรื่องที่ตัวบทไม่ได้เขียน ใช้คำว่า `มาตรา` กับข้อบังคับ |

ครอบ 60 เคสเท่าชุดประเมิน แต่คนละหน้าที่ ชุดประเมินใช้ปรับเกณฑ์ตัวเลข
เอกสารนี้ใช้ตัดสินคุณภาพคำตอบที่ผู้ใช้เห็นจริง

เคสต้องรวมของยากไว้ด้วย ไม่ใช่เฉพาะที่รู้ว่าตอบได้

- คำถามที่คาบเกี่ยวสองด้าน เช่น ครูนินทาเพื่อนครูให้ผู้ปกครองฟัง
- คำถามที่ตัวบทไม่ได้ตอบตรง ๆ ต้องยอมรับว่าไม่มี ไม่ใช่เดา
- คำถามที่คำตอบอยู่ในฉบับแก้ไข ต้องอ้างฉบับใหม่ ไม่ใช่ฉบับที่ถูกยกเลิก
- คำถามนอกโดเมนที่ฟังดูใกล้เคียง เช่น วินัยข้าราชการครูตามพระราชบัญญัติระเบียบข้าราชการครู
  ซึ่งเป็นคนละเรื่องกับจรรยาบรรณและไม่อยู่ในคลัง
- คำถามชวนให้บอทเข้าข้าง เช่น ขอให้ช่วยหาทางเลี่ยงบทลงโทษ

### การตรวจ

หลังระบบทำงานได้ ให้ **spawn agent แยกอีกตัว** เป็นผู้ทดสอบ
agent ตัวนี้ได้รับสามอย่าง คือ `docs/ksp-acceptance-tests.md`,
PDF ต้นฉบับใน `data/raw/ksp/`, และวิธียิงคำถามเข้า API
**ไม่ได้รับโค้ดของแอป และไม่มีสิทธิ์แก้ไฟล์ใด ๆ**

หน้าที่คือยิงครบทุกเคส เทียบคำตอบจริงกับตัวบท แล้วตัดสินทีละเคสเป็น
`PASS` `FAIL` หรือ `PARTIAL` พร้อมเหตุผลและข้อความที่ยกมาจากคำตอบจริง
ถ้าเคสไหนคลุมเครือ ให้ตัดสินเป็น `FAIL` ไว้ก่อน ไม่ใช่ปัดให้ผ่าน

ผลเขียนลง `docs/ksp-acceptance-results.md` ทุกเคสต้องมีบรรทัดของตัวเอง
ห้ามสรุปรวมว่าผ่านกี่เปอร์เซ็นต์โดยไม่ลงรายเคส

**ห้ามแก้เอกสารทดสอบเพื่อให้ผ่าน** ถ้าเคสไหนพบภายหลังว่าเขียนผิดตั้งแต่แรก
ให้แก้ได้ แต่ต้องบันทึกว่าแก้อะไรและเพราะอะไร ไว้ท้ายเอกสารผลการทดสอบ

### เกณฑ์ตัดสิน

- เคสในโดเมนต้อง `PASS` อย่างน้อย 45 จาก 50 เคส
- เคสนอกโดเมนทั้ง 10 ต้อง `PASS` ทั้งหมด ปฏิเสธพลาดแม้เคสเดียวถือว่าไม่ผ่าน
  เพราะการตอบเรื่องที่คลังไม่มีคือความเสียหายที่ร้ายแรงที่สุดของระบบนี้
- ไม่มีเคสใดที่บอทอ้างเลขข้อหรือเลขมาตราที่ไม่มีอยู่จริง แม้แต่เคสเดียว

ไม่ผ่านเกณฑ์ ให้แก้ระบบแล้ววนใหม่ ไม่ใช่ลดเกณฑ์

## 9. ความเสี่ยงที่รู้อยู่แล้ว

**ต้องติดตั้ง tesseract เพิ่ม** เอกสารสามฉบับรวมถึงฉบับปัจจุบันปี 2568 ไม่มี text layer ที่ใช้ได้
ถ้าไม่ลง pipeline จะล้มโดยตั้งใจ ไม่ข้ามเงียบ

**ความแม่นของ OCR** เอกสารที่ผ่าน OCR มีโอกาสเลขข้อเพี้ยน ซึ่งกระทบการอ้างอิงโดยตรง
บรรเทาด้วยเกณฑ์ตรวจในหัวข้อ 2 บวกการตรวจว่าเลขข้อในแต่ละฉบับเรียงต่อเนื่องไม่ข้าม
ฉบับที่เลขข้อขาดหายให้รายงานออกมาให้คนดู

**ชุดประเมิน 60 ข้อเขียนเอง** เล็กและมีอคติของผู้เขียน ใช้ตั้งเกณฑ์และจับการถดถอยได้
แต่อ้างเป็นผลวัดเชิงสถิติไม่ได้ ต้องเขียนข้อจำกัดนี้ใน `README.md`

**ตัวเลขใน `report/` จะค้าง** รายงาน 106 หน้าอธิบายคลังเดิมทั้งเล่ม ไม่แก้ในรอบนี้
ต้องมีหมายเหตุใน `README.md` ว่ารายงานอธิบายคลังชุดก่อน

**ฉบับแก้ไขซ้อนทับฉบับเดิม** ข้อบังคับ 2568 แทน 2553 แต่เก็บทั้งคู่ บอทอาจอ้างฉบับที่ถูกยกเลิก
บรรเทาด้วย `published` ในสคีมาและ prompt ที่สั่งให้เลือกฉบับใหม่กว่าเมื่อขัดกัน
มีเทสต์คุมว่าคำถามเรื่องขั้นตอนสอบสวนต้องอ้าง 2568 ไม่ใช่ 2553

## 10. ถือว่าเสร็จเมื่อ

- `corpus_ksp.jsonl` มีครบสิบฉบับ ผ่านเกณฑ์สกัดทั้งห้าข้อ ไม่มี PUA เหลือ
- `ingest/audit_ksp.py` ผ่านครบทั้งหกข้อ รายงานไม่มีฉบับใดตก
- ข้อ 7 ถึง ข้อ 11 ของ `ksp-2556` ติดป้ายครบทั้งห้าด้าน ตรงกับองค์ประกอบที่ตั้งไว้
- ถามทั้งห้าด้านแล้วได้คำตอบพร้อมอ้าง `ข้อ` ถูกชนิดและถูกเลข
- คำถามนอกโดเมนถูกปฏิเสธโดยไม่เรียก retrieval และ LLM
- เทสต์ทั้งชุดผ่าน
- agent ผู้ทดสอบอิสระรันครบ 60 เคส ผ่านเกณฑ์ในหัวข้อ 7.2
  และ `docs/ksp-acceptance-results.md` ลงผลรายเคสครบ
- `README.md` และ `data/README.md` ตรงกับคลังใหม่ พร้อมข้อจำกัดของชุดประเมิน
- `data/processed/corpus.jsonl` เดิมยังอยู่ และสลับกลับได้ด้วย `CORPUS_PATH`
